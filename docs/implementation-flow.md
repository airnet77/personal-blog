## 阶段 0 · 准备

### 目标
把「你没有我造不出来的东西」准备好：GitHub 仓库与 Cloudflare 账号。

2. 你完成后，核验仓库地址是否可访问、账号是否就绪
3. 确认无误后进入阶段 1

### 🟨 你做（你）

- 打开 <https://github.com/signup>

**③ 创建 GitHub 仓库**
- 打开 <https://github.com/new>

- 可见性：**Public**（推荐，为了评论功能）
- **不要**勾选 README / .gitignore / license（保持空仓库，避免冲突）
- 点 Create repository

**④ 把仓库地址发我**
- 格式：`https://github.com/你的用户名/personal-blog`

### 🔗 交接点
**我停下来等你。** 收到仓库地址后才进入阶段 1。

## 阶段 1 · 项目骨架与主题

### 目标
一个能在本地跑起来、带明暗主题切换、SEO 基础已就位的空站点。

### 🟦 我做（AI）
1. 在当前空目录初始化 Astro 项目（`pnpm create astro`，minimal 模板 + TypeScript strict）
2. 安装并锁定依赖：`astro@7.4.1`、`@tailwindcss/vite@4.3.3`、`@tailwindcss/typography@0.5.20`、`@astrojs/sitemap@3.7.4`、`@astrojs/check`、`typescript`
3. 写 `astro.config.mjs`：`site`、Tailwind Vite 插件、sitemap 集成、Shiki 高亮
4. 写 `src/consts.ts`：站点名、作者、`SITE_URL`、简介、社交链接
5. 写 `src/styles/global.css`：Tailwind 入口、typography 插件、中文字体栈、暗色变量
6. 写 `BaseLayout.astro`：`lang="zh-CN"`、SEO meta（title/description/canonical/OG）、**内联防闪烁脚本**
7. 写 `Header.astro` / `Footer.astro` / `ThemeToggle.astro`
8. 写 `src/pages/index.astro` 占位首页
9. 配置 `.gitignore`、`.node-version`（内容 `24`）、`tsconfig.json`、`package.json` 的 `packageManager` 字段
10. 跑 `pnpm check` + `pnpm build` + `pnpm dev`，确认无报错并启动成功
11. 打印本地访问地址给你

### 🟨 你做（你）
1. **确认能打开**：我在本地起的 `http://localhost:4321`，你打开看首页是否正常、点击主题按钮能否切换明暗
2. **提供站点信息**（我用于填 `consts.ts`）：
   - 站点名称（例：`某某的博客`）
   - 作者署名
   - 一句话简介（用于首页与 SEO）
   - 社交链接（GitHub / X / 邮箱，没有就说「无」）
3. **可选**：一个 favicon（`.svg` 或 `.png`）。不提供的话我用一个占位 SVG

> ⚠️ 若我和你在**不同机器**上，`localhost` 你打不开。这种情况下改用我构建后给你截图 + 你在阶段 4 线上验收。请先告诉我你的情况。

### 🔗 交接点
**我等你确认本地访问正常 + 提供站点信息**，然后进入阶段 2。

### ✅ 验收标准
- [ ] `pnpm build` 成功，`dist/index.html` 存在
- [ ] 页面 `lang="zh-CN"`，标题正确
- [ ] 明暗切换可用，刷新后不闪白、状态保持
- [ ] 375px 宽度下无横向滚动

### ⏱ 预估
1 轮（我这侧约 20–30 分钟工作量）

## 阶段 2 · 内容模型与全站路由

### 目标
博客的「骨架页面」全部可用：能写文章、能按标签/时间浏览。

### 🟦 我做（AI）
1. 写 `src/content.config.ts`：`glob()` loader + zod schema（`z` 从 `astro/zod` 导入）
2. 写共用的**文章过滤函数**（过滤 `draft` 与未来日期），全站统一调用
3. 写示例文章 3 篇（其中 1 篇 `draft: true`，用于验证过滤生效）
4. 路由与页面：
   - `/` 首页（最新文章列表 + 简介）
   - `/blog/` 文章列表 + 分页（每页 10 篇）
   - `/blog/[slug]/` 文章详情（含 TOC、阅读时间、上一篇/下一篇）
   - `/tags/`、`/tags/[tag]/`
   - `/archive/` 按年月归档
   - `/about/` 关于页
   - `/404` 自定义 404
5. 组件：`PostCard`、`TableOfContents`、`TagList`
6. 中文字排版调优（行高、段距、代码块滚动）
7. 跑构建并逐页抽查

### 🟨 你做（你）
1. **确认标签命名习惯**（影响 URL 与导航）：
   - 标签用中文还是英文？（中文标签的 URL 会被百分号编码，功能没问题，只是地址长一点）
   - 常用标签想好 3–6 个就行，别一上来就十几个
2. **提供首批内容素材**（三选一）：
   - A. 给 1–3 篇真实文章（Markdown 或纯文本都行，我来整理 frontmatter）
   - B. 只给标题与大纲，我扩写成文
   - C. 先用示例文章占位，你之后自己补
3. **可选**：头像或首页配图

### 🔗 交接点
**我等你答复标签命名 + 素材选择**（选 C 也算答复），然后进入阶段 3。

### ✅ 验收标准
- [ ] 草稿文章**不出现**在任何列表、标签页、归档中
- [ ] 标签页能正确聚合，点标签进入后只显示该标签文章
- [ ] 归档页按年月倒序分组正确
- [ ] 文章页 TOC 锚点可点击跳转
- [ ] 分页第 2 页可访问
- [ ] 404 页返回正确状态

### ⏱ 预估
1 轮

## 阶段 3 · 搜索 / 评论 / RSS / SEO

### 目标
补齐「博客该有的功能」。这一阶段的搜索与 RSS 全自动，评论需要你配置。

> ✅ **已完成（2026-10-20）**：搜索、RSS、Sitemap、robots.txt、JSON-LD 全部上线且有验证；
> 评论按要求**暂时搁置**——`Comments.astro` 已做成开关，配好 `src/consts.ts` 的 `GISCUS` 即可启用，不改其他代码。

### 🟦 我做（AI）
1. **搜索**：接入 `astro-pagefind`，文章正文加 `data-pagefind-body`、导航页脚加 `data-pagefind-ignore`，写 `/search/` 搜索页
2. **RSS**：`/rss.xml`，最近 20 篇，过滤草稿
3. **Sitemap**：排除 `/404` 与 `/search/`
4. **robots.txt**
5. **SEO**：每页独立 title/description、canonical、OG 标签、文章页 `BlogPosting` JSON-LD
6. **评论**：`Comments.astro` 组件（懒加载 + 明暗主题跟随 + 失败静默），**先用占位参数**，拿到你的 ID 后填入
7. 跑构建，确认 `dist/pagefind/` 生成

### 🟨 你做（你）—— 配置 giscus（我无法代劳，需要你的 GitHub 身份）

1. 打开你的仓库 → **Settings** → 左侧 **General** → 拉到 **Features**
2. 勾选 **Discussions**
3. 进入仓库顶部 **Discussions** 标签 → 点 **New discussion** 旁的分类下拉，选 **Announcements**（若是空白，去 Discussions 设置里新建一个分类，推荐命名 `Comments`）
4. 打开 <https://giscus.app/zh-CN>
5. 在「仓库」输入框填 `你的用户名/personal-blog`，按提示**安装 giscus App**（只需授权这一个仓库）
6. 「Discussion 分类」选择你刚建的那个
7. 页面下方会生成一段代码，请把其中**这两个值**复制给我：
   - `data-repo-id="R_xxxxxx"`
   - `data-category-id="DIC_xxxxxx"`
8. 顺便确认「映射关系」使用 **pathname**（默认即可）

> 💡 如果这一步你觉得麻烦，也可以说「先不做评论」，我会把组件做成开关，随时可插。

### 🔗 交接点
**我等你给 `repo-id` / `category-id`**（或明确说不做评论），然后进入阶段 4。

### ✅ 验收标准
- [ ] `/search/` 能搜到中文关键词
- [ ] `dist/pagefind/` 存在
- [ ] `/rss.xml` 格式合法、含正确绝对链接、无草稿
- [ ] `/sitemap-index.xml` 不含 `/404`
- [ ] 文章页 view-source 能看到 canonical 与 JSON-LD
- [ ] 评论组件懒加载，不拖慢首屏

## 阶段 4 · 部署上线

### 目标
`https://xxx.pages.dev` 可公开访问。

### 🟦 我做（AI）
1. 本地 `git init` → 提交 → 关联远程仓库 → 推送（若你的机器上未配 Git 凭据，我会改用你推送的方式）
2. 给你一张**精确到字段**的 Cloudflare 配置卡（见下方 🟨）
3. 你部署后，若构建失败：你贴日志给我，我定位并修复，再推一版
4. 你拿到域名后，我回填 `consts.ts` 的 `SITE_URL` 并推第二版
5. 二次部署完成后核验线上页面

### 🟨 你做（你）

**① 推送代码**（如果我推送失败时由你做）
- 确认仓库已有代码（刷新 GitHub 页面能看到文件）

**② 在 Cloudflare 创建 Pages 项目**
1. 打开 <https://dash.cloudflare.com/> → 左侧 **Workers & Pages**
2. 点 **Create**（或 Create application）→ 选 **Pages** → **Connect to Git**
3. 授权 GitHub（首次会跳转授权页，选**仅授权这一个仓库**更安全）
4. 选中你的 `personal-blog` 仓库 → **Begin setup**

**③ 填写构建设置（关键，照抄）**

| 字段 | 填什么 |
| --- | --- |
| Project name | `personal-blog`（决定最终网址 `personal-blog.pages.dev`，可改） |
| Production branch | `main` |
| Framework preset | `Astro` |
| Build command | `pnpm build` |
| Build output directory | `dist` |

**④ 添加环境变量（这一步不做，构建必失败）**

在 **Environment variables** 里加两条：

| 变量名 | 值 | 为什么 |
| --- | --- | --- |
| `NODE_VERSION` | `24` | Astro 7 要求 Node ≥ 22.22.0，平台默认 22.16.0 不够 |
| `PNPM_VERSION` | `12` | 与本地 pnpm 12.11.2 对齐，避免 lockfile 不兼容 |

**⑤ 点 Save and Deploy**，等待 1–3 分钟
- 构建成功：拿到类似 `https://personal-blog-abc.pages.dev` 的域名
- 构建失败：把**完整报错日志**复制给我

**⑥ 把最终域名发我**

### 🔗 交接点
**我等你给域名**（或构建报错日志）。

### ✅ 验收标准
- [ ] 线上首页可访问，HTTPS 有效（地址栏有锁）
- [ ] 文章页、标签页、搜索页均可访问
- [ ] 手机浏览器打开正常
- [ ] 构建日志无红色报错

### ⏱ 预估
30 分钟（含等待构建）

## 附录 B · 常见故障速查

| 现象 | 最可能的原因 | 谁修 |
| --- | --- | --- |
| Cloudflare 构建报 Node 版本错误 | 没设 `NODE_VERSION=24` | 你改环境变量，我确认 |

| 搜索无结果 | pagefind 索引未生成 / 没加 `data-pagefind-body` | 我修 |
| 评论加载不出来 | 前端脚本被拦截 / 接口报错 / 评论被转待审 | 看 `/api/comments` 返回与 `/api/health`；去后台「评论管理」看待审 |

| 页面中文空格异常 | Astro 7 `compressHTML: 'jsx'` 影响内联元素 | 我修 |
| 自定义域名想加 | 后台加域名 + 改一次 `SITE_URL` | 你做后台，我改常量 |

3. 发一条含链接的评论 → 前台红字「评论违规，未发送：不允许链接」。
4. 后台 →「评论管理」筛选「违规」→ 能看到刚才那条的留档与原因。
